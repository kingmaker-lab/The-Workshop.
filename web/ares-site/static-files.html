// 01 — FILE RESOLUTION

Do URL ao arquivo.
Sem atalhos.

O ARES não confia no caminho recebido. Primeiro valida cada componente. Depois percorre o filesystem a partir de um descritor autorizado, sem seguir links simbólicos.

01 / ROUTE/static/*GET / HEAD
02 / VALIDATEPath rulesASCII · sem .. / %
03 / RESOLVEopenat()O_NOFOLLOW
04 / INSPECTfstat()regular · ≤256 KiB
05 / DELIVERread/sendMIME + Content-Length

O diretório public/ é a única origem autorizada e precisa ser administrado como conteúdo confiável. Não existe upload público nesta versão. A URL não é decodificada; formatos ambíguos são recusados.

// 03 — SECURITY BY DESIGN

O que a v0.4 recusa.

Três fronteiras explícitas: sintaxe dos caminhos, estrutura do filesystem e volume de dados retornado.

01 / PATH TRAVERSAL↛

Fora da raiz, não.

Rejeita ../, caminhos codificados, barra invertida, componentes vazios, arquivos ocultos e URLs com query na rota estática.

02 / DESCRIPTORS⊗

Sem seguir symlinks.

openat() percorre cada componente com O_NOFOLLOW. fstat() aceita somente arquivos regulares; diretórios e FIFOs não são servidos.

03 / RESOURCE BOUNDS≦

Limites verificáveis.

Extensões MIME permitidas explicitamente, arquivos de até 256 KiB, leitura em blocos de 16 KiB e Content-Length calculado por fstat().
