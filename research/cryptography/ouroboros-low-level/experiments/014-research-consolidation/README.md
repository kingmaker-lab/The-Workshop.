# OUROBOROS — EXP-014: Research Consolidation & Independent Conformance

**The Workshop / WolfPack Crypto Lab**  
**Branch:** exp-014-research-consolidation  
**Role:** final consolidation experiment before the EXP-015 functional-validation phase.

## 1. Objective

EXP-014 does not propose a new cipher variant or modify EXP-008. It consolidates the evidence from EXP-008 through EXP-013, records what each experiment actually measured, and adds an independent specification oracle to cross-check the canonical Python implementation.

The core conformance check re-expresses the published EXP-008 equations in a separate module without importing the canonical feistel16.py. It then compares the two implementations over all 65,536 plaintext blocks for five fixed master keys.

This is an independent Python reference model, not a second optimized production implementation. The repository currently contains no separate C/Assembly implementation of the EXP-008 Feistel cipher. The distinct 64-bit ouroboros_step state transition must not be described as an implementation of this 16-bit cipher.

## 2. Consolidated evidence register

| Experiment | Evidence type | Confirmed scope | Explicit boundary |
|---|---|---|---|
| EXP-008 | Functional and exhaustive-domain tests | 16-bit Feistel, 8 rounds; five canonical KAT sets now in EXP-014; existing tests perform full round trips for three keys | 32-bit master-key space not exhaustive; toy cipher |
| EXP-009 | Exact component analysis | Full 256×256 DDT and 256×256 Walsh LAT of the 8-bit round function; max differential probability 0.25; max absolute correlation 0.5 | Round function only, not full Feistel cipher |
| EXP-010 | Exact restricted-slice analysis | 16 one-bit input differences and 16×16 weight-one mask correlations for 1–8 round prefixes, three keys | Not full 16-bit DDT/LAT |
| EXP-011 | Exact transition model + selected full-domain observations | Differential Markov propagation; selected fixed-key distributions over 65,536 blocks; signed linear trails/hulls and direct Walsh checks | Differential Markov hull is not silently equated with fixed-key DDT; selected starting differences/masks only |
| EXP-012 | Structural proof + deterministic sample | Fixed-context internal state transition is bijective and has an inverse; 8,192-key campaign | Not exhaustive over 2^32 master keys |
| EXP-013 | Exact algebraic relation + bounded schedule-preimage search + sample statistics | Telescoping XOR identity; 256-candidate preimage search for a fully known eight-byte round-key schedule; 2,016 output-bit pairs and 1,020 byte deltas | Not ciphertext-only recovery; no all-key proof; pairwise statistics do not prove higher-order independence |

## 3. EXP-008 frozen specification

- Block: 16 bits, split into two 8-bit halves.
- Master key: 32 bits, expanded into eight 8-bit round keys.
- Round function: F(R,K)=P8(S(R XOR K)).
- S-box: PRESENT 4-bit S-box applied independently to high and low nibbles.
- P8: output bit j receives input bit P8[j], with LSB-based indexing.
- Key schedule: KS1 as specified in the EXP-008 README, unchanged.
- Feistel update: L(r+1)=R(r), R(r+1)=L(r) XOR F(R(r),K(r)).

The reference model keeps its own S-box and P8 declarations and its own transcription of the equations. It imports no functions or constants from the canonical cipher module.

## 4. Independent conformance campaign

Five master keys are fixed:
- 0x00000000
- 0x00000001
- 0x01234567
- 0x89ABCDEF
- 0xFFFFFFFF

The campaign includes:
- 40 round-key byte comparisons against the independent reference schedule;
- 25 frozen known-answer plaintext/ciphertext checks;
- 65,536 plaintext comparisons per key (327,680 total);
- 65,536-element uniqueness/permutation check for each key;
- reference encryption/decryption round trips over the full block domain for each key;
- canonical decryption checks against known-answer vectors.

These checks establish conformance of the canonical Python implementation to the independent transcription for the selected five keys over the complete block domain. They do not prove the specification is secure, and they do not cover every possible master key.

## 5. Known-answer vectors

The frozen KAT set is stored in known_answers.json. It includes five plaintexts for each of the five master keys. These vectors are generated by the independent reference model and checked against the canonical implementation.

## 6. Reproduction

Run EXP-014 from its directory:

~~~bash
python3 -m unittest -v
python3 conformance.py
~~~

Run the historical experiment test suites in isolation:

~~~bash
for d in \
  ../008-reduced-feistel \
  ../009-round-function-analysis \
  ../010-feistel-trail-analysis \
  ../011-multiround-trail-search \
  ../012-key-schedule-analysis \
  ../013-related-key-dependency-analysis
do
  (cd "$d" && python3 -m unittest discover -s . -p 'test_*.py' -v) || exit 1
done
~~~

Each experiment is run in its own process/directory to avoid module-name collisions such as different feistel16.py files.

## 7. Implementation inventory and gaps

- Canonical EXP-008 cipher implementation: Python.
- Independent EXP-014 specification oracle: Python, deliberately separate transcription.
- C/Assembly implementation of the EXP-008 Feistel cipher: not present in the audited experiment tree.
- The 64-bit Assembly ouroboros_step implementation is a different construction and is excluded from cross-implementation conformance claims.
- Formal cryptographic security proof and independent expert review: not part of EXP-014.

A future second implementation must be derived from the frozen specification, not ported by copying the oracle line-for-line. It should receive its own language-specific tests and be compared against the same KAT and exhaustive domain harness.

## 8. Research conclusions carried forward

1. EXP-009 demonstrates strong differential and linear relations in the isolated 8-bit round component.
2. EXP-010 shows substantial attenuation in the measured one-bit/basis-mask slices as Feistel rounds accumulate, but does not test all differences/masks.
3. EXP-011 separates differential Markov estimates from actual selected fixed-key distributions and distinguishes single linear trails from signed hulls.
4. EXP-012 establishes invertibility of the internal KS1 state transition for a fixed round.
5. EXP-013 establishes an exact telescoping XOR relation among emitted subkeys and shows bounded recovery from a fully known subkey stream. Its two sample campaigns did not show strong pairwise output-bit dependencies or catastrophic Hamming diffusion in the tested delta family.

None of these statements amounts to a production security claim. The 16-bit block and 32-bit key are intentionally toy-sized.

## 9. EXP-015 transition gate

EXP-014 is the last research consolidation step. EXP-015 begins a separate functional-verification phase:
- freeze the specification, vectors, and source revision;
- test encryption/decryption and input validation;
- verify domain/permutation properties;
- compare all implementations against independent KATs;
- perform regression, deterministic fuzzing, build and portability checks;
- keep functional correctness and cryptographic security as separate release gates.

No production use is authorized by passing EXP-014.
