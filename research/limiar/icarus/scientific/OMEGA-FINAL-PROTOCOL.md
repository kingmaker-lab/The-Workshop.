# ICARUS OMEGA | Final Ascension — terminal study design v0.1
2026-11-25. Research only. Proposed terminal design, not yet a locked executable preregistration. HELIOS is already EXP-005; OMEGA is the distinct terminal study within ATHENA/ATLAS, not a replacement. No extension of the experimental cycle merely because a target is missed.

## Scope and freeze
One final bounded engineering implementation: native C executable, identical optimized feature extraction for candidate and FULL, cheap means/variances and optional lag differences, recoverable hierarchical cheap classification (dynamic four classes / static two classes on MotionSense; expansion permits all six classes), causal signed-benefit policy with prefix cap floor(i*q/4), no forced final fill. Full baseline computes every feature, all six class scores, no redundant gate or selector. LITE uses candidate cheap prediction only; STATIC exact quota is descriptive. Same training model/scales, arithmetic precision, compiler flags, input and output contract. Validate numerical equivalence of fused statistics against reference two-pass implementation on bounded synthetic fixtures and development data before freeze; no artificial workload. Preserve all previous results. One engineering build and smoke on non-final data; bug fixes only before freeze, document them. Freeze source commit, executable hash, dataset hashes, split, thresholds, calibration results and analysis before reading held-out outcomes. Python may prepare data/analyze output, never required for native inference. No changing candidate after final evaluation.

## External real workload
MotionSense original public dataset https://github.com/mmalekzadeh/motion-sense (24 participants, 50 Hz iPhone 6s, walking, upstairs, downstairs, jogging, sitting, standing). Six classes, different activity set than UCI HAR (jogging replaces laying); do not compare raw accuracy across datasets as an improvement. New corpus relative to prior experiments, not zero-shot transfer: fit and calibrate on its development participants. Use total acceleration (gravity + userAcceleration) and rotationRate. Non-overlapping 128-sample windows, never crossing recording or participant; preserve source row order; explicitly reject invalid rows/trials rather than impute silently. Log complete class and subject counts. No personal attributes in model or published outputs. Fixed allocation: shuffle sorted IDs 1..24 with Python random.Random(20261125).shuffle, first 8 fit, next 4 signed-benefit fit, next 4 threshold tune, final 8 untouched test. Verify actual IDs and format before freeze without evaluating final labels. No original MOTION test subjects reused to tune. External corpus is a new experimental context, not proof of independent hardware replication.

## Candidate selection and primary evaluation
One finite calibration grid, q in {1,2,3} (25/50/75% maximum expansion), signed-benefit threshold in {0,.02,.05,.10}, expand only if score > threshold and prefix permits. Estimate signed gain of all-class FULL versus hierarchical LITE, conditioned on cheap predicted group and within-group margin, shrinkage table as in KINESIS. Use only benefit-fit subjects for table. Select one of 12 settings using only tuning participants: among settings with observed macro subject loss <=1 pp and geometric CPU ratio <=0.5 choose highest macro accuracy, then lower CPU ratio, then lower q, then higher threshold. If none, among CPU-feasible settings choose highest macro accuracy with same ties; if none CPU-feasible choose smallest CPU ratio, then highest macro accuracy, lower q, higher threshold. No post-test selection. Calibration timing uses five randomized paired repetitions per batch; same aggregation as primary. Report chosen configuration and entire calibration grid. Fixed primary batch max64, never cross subject/trial; no retuning across sessions.

One final evaluation on eight held-out subjects. Five measurement sessions, seven paired randomized repeats per batch, one warmup per arm; same held-out windows each session, not additional quality observations. Quality macro subject difference FULL minus OMEGA in percentage points, verify predictions identical across timing repeats/sessions. One-sided approximate 95% Student t upper bound across eight subject differences (df7). CPU: per session sum median batch CPU by subject, geometric mean paired ratios equally weighted by subject; average log ratios across five sessions, one-sided approximate t upper bound df4 and exponentiate. Independent representative subject/block means and approximate normality are assumptions, same machine; report limitation, no power guarantee. Primary conjunction quality upper <=1 pp and CPU upper <=0.5. Weaker CPU superiority upper <1 reported separately, no promotion to primary. Absolute macro/pooled accuracy, class recall/confusion, LITE and STATIC descriptive, all individual results. If failed, report failure to establish target (not proof of inferiority). No changes or sample extensions.

## System limits and memory
Fixed secondary stress grid batch max1/16/64/256, on one frozen held-out replay per size, same candidate parameters, report CPU, wall, throughput, p50/p95/p99 latency per batch, expansion fractions, and prefix violations; max 15 s per arm per size, deterministic source-order replay, no synthetic padding, no artificial CPU/memory pressure. Stop at cap; report completed counts, compare common completed prefix for descriptive comparisons; do not treat repeated replay as new quality data. No extrapolation to untested loads. Native process peak RSS via fresh processes using same bounded buffers and full identical data pipeline; measure FULL and OMEGA in each of five sessions, log ratio and approximate one-sided t upper bound <=0.75 for 25% memory target. Report absolute KiB and timing scope. Native resident kernel primary; separate file-to-prediction timing includes reading/parsing, not live acquisition or mobile hardware. Standalone executable must run with no Python dependency and reproducible outputs. Record all logical prefix violations; native independence and budget integrity are engineering checks, not confidence intervals.

Passive memory floor 256 MiB, thermal stop 80 C, no sudo, no parallel stress, no intentional exhaustion. Use sampled guards before batches and during replay, disclose limitations. At safety stop retain logs/checkpoints and allow at most one safe resumption of the affected session with same hashes; no weakening guards, no replacing slow or unfavorable results. Incomplete required primary evidence -> inconclusive; preserve partial data. Performance is for the actual low-resource machine, not all architectures.

## Terminal decision
PRIMARY PASSED if both prespecified statistical quality and CPU bounds pass and no recorded logical violations. FULL ORIGINAL GOALS MET only if memory upper bound also passes and native executable integrity checks pass. Otherwise report partial or not established as applicable. Incomplete/invalid evidence -> inconclusive, not a license to extend sample or choose a favorable configuration. Publish all outcomes and limits in ledger, paper and portal. No OMEGA-02 to chase targets. ATH-006 independent reproduction and ATH-007 manuscript/archive are separate verification/publication tasks, not new optimization cycles. Further improvements, if desired later, belong to a separately scoped successor project, not this frozen research version.
